# Adamu Solar --- Coding Standards

**Document ID:** AS-CODE-001\
**Version:** 1.0\
**Status:** Baseline for implementation phases

## 1. General principles

-   Follow the approved requirements, scope, brand guide, and UI/UX
    specification.
-   Prefer clear, simple, maintainable code over unnecessary
    abstraction.
-   Keep the MVP lightweight; avoid adding dependencies without a
    requirement.
-   Use JavaScript, not TypeScript, for this project.
-   Follow the conventions generated by the installed Next.js version
    unless the project documents a reason to change them.

## 2. React and Next.js

-   Use the App Router structure.
-   Prefer Server Components by default.
-   Add `"use client"` only when a component requires client-side state,
    event handlers, or browser-only behavior.
-   Use semantic HTML and native controls where practical.
-   Keep page content and reusable UI components separated when this
    improves clarity.
-   Do not create API routes or server actions without an approved need.
-   Keep the site's five-page MVP scope.

## 3. JavaScript

-   Use `const` by default and `let` when reassignment is needed.
-   Avoid `var`.
-   Use descriptive names.
-   Avoid duplicated logic when a small shared utility or component is
    clearly beneficial.
-   Handle errors explicitly at integration boundaries.
-   Do not leave debug logs or dead code in the production version.

## 4. Styling

-   Use Tailwind CSS for the agreed design system.
-   Keep colors and typography aligned with the approved brand guide.
-   Prefer consistent spacing, responsive utilities, and reusable
    patterns.
-   Do not add a second styling framework without approval.
-   Test English and Amharic text lengths.
-   Maintain keyboard focus visibility and sufficient contrast.

## 5. Accessibility and content

-   Use one clear main heading per page and logical heading order.
-   Provide visible form labels and useful validation feedback.
-   Provide meaningful alt text for informative images.
-   Use empty alt text for purely decorative images.
-   Do not rely only on color, hover, or icons to communicate meaning.
-   Publish only client-approved facts, project photos, credentials, and
    testimonials.

## 6. Dependencies and assets

-   Prefer built-in Next.js capabilities where sufficient.
-   Review package size and maintenance status before adding
    dependencies.
-   Use approved and legally usable assets.
-   Optimize images and avoid unnecessarily large downloads.
-   Do not commit copied stock assets without confirming their usage
    rights.

## 7. Security and privacy

-   Never commit secrets or customer inquiry data.
-   Do not put secret keys in client-side code.
-   Validate inquiry data at the receiving endpoint/service.
-   Do not claim a form submission succeeded unless the delivery service
    confirms it.
-   Publish contact information only with Adamu's approval.
-   Use HTTPS for the live website.

## 8. Quality checks

Before a change is committed: - Run the relevant lint command. - Run a
production build when appropriate. - Test the affected route and
responsive behavior. - Check keyboard use and visible focus. - Review
the Git diff. - Confirm no unapproved features or business claims were
added.

## 9. AI coding-agent rules

When using an AI coding agent: 1. Read `README.md` and the relevant
documents in `docs/` first. 2. Follow the approved scope; do not expand
it without asking. 3. Do not invent client facts, translations,
testimonials, prices, certificates, or project details. 4. Make one
focused implementation slice at a time. 5. Report files changed,
commands run, test results, and unresolved issues. 6. Do not claim tests
passed unless the commands were actually run and their results checked.
7. Do not deploy or publish without explicit approval.
